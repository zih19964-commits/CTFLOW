# 独立连接与工作流验收

验收日期：2026-10-23。

> 2026-11-18 更新：每个 Worker 可选择 Chat Completions、OpenAI Responses 或 Anthropic Messages；API Key 在 Windows 使用 DPAPI、其他平台使用 Fernet 加密写入 SQLite；MCP stdio 工具已接入并通过自动化与 DeepSeek V4.1 真实链路验证。正式测试 272 passed，含保留原型的联合回归 321 passed，Ruff 全仓检查通过，44 个文件格式检查通过。

每个 Worker 独立保存协议、`base_url`、API Key、模型和 `extra_body`。节点在并发限制内建立所属 Worker 的客户端，结束后关闭；同一工作流可同时使用不同供应商和协议。API Key 在 Windows 以 DPAPI、其他平台以 Fernet 密文保存在本机 Worker 数据库记录中，密码输入框以掩码显示，公开 JSON、运行快照及日志进行脱敏。

Worker 配置窗使用当前未保存的连接刷新模型；`/models` 针对当前选中节点的 Worker，`/models <id>` 指定 Worker。候选列表按 Worker 隔离。连接在刷新期间被修改时，旧接口返回的结果会被丢弃。

## 已保存的新增工作流

| 命令 | 结构 | 输出 |
| --- | --- | --- |
| `/flow serial-111` | A → B → C | 事实调查、推理分析后的独立复核 |
| `/flow debate-312` | A/B/C → D → E/F | 基于同一证据清单的支持与反对判断 |
| `/flow decision-3121` | A/B/C → D → E/F → G | 正反分析后的综合裁决 |

新增六个可复用 Worker：`scout-facts`、`scout-practice`、`scout-risks`、`synthesis`、`support`、`challenge`；最终复核与裁决引用 `judge`。三个检索 Worker 配置 Qwen 服务端联网搜索与强制搜索参数，依据[官方参数说明](https://help.aliyun.com/zh/model-studio/web-search)。切换供应商时需调整该 Worker 的附加参数。

用户已确认将原全局连接复制为六个既有 Worker 的独立起始配置，应用配置中的全局连接项已移除。追加预设后，本机共有 12 个 Worker、5 套工作流；原来的 2 套工作流、3 次运行以及既有 Worker 的任务内容均保留。
