# 入门指南

在项目根目录运行 `.\.venv\Scripts\ctflow.exe` 打开 FLUX 工作台。上方是工作流图，右侧是节点列表，下方是所选节点的输出，底部输入任务和命令。

## 配置模型

通过 `/worker <id>` 打开 Worker 配置，协议可选 Chat Completions、OpenAI Responses 或 Anthropic Messages。`base_url` 填该协议的服务根地址，API Key 填该服务的密钥，模型填写该接口支持的 ID。附加请求参数使用 JSON 对象，例如 `{"enable_thinking": false}`；这些参数只用于当前 Worker。多个 Worker 可以各自使用不同供应商、协议和密钥，节点会按装配的 Worker 连接执行。

`/models` 读取当前选中节点所引用 Worker 的模型列表，`/models <worker-id>` 指定其他 Worker。Worker 配置窗口的“刷新模型”按钮使用正在编辑的连接，保留其他未保存字段。模型可从列表中选择，也可填写准确 ID。Qwen 的模型 ID 和地域接口应以账户可用范围为准，参见[官方首次调用说明](https://www.alibabacloud.com/help/en/model-studio/first-api-call-to-qwen)与 [Qwen3.8-Max 模型页](https://www.alibabacloud.com/help/en/model-studio/qwen3-8-max)。

应用级配置保存在 `config/config.json`。`workspace` 与 `data_dir` 的相对路径以配置文件所在目录解析；通常分别为 `..` 和 `../data`。`concurrency` 控制同时请求的节点数量，`timeout` 控制单次请求总时限，`max_tokens` 控制输出长度，`max_tool_rounds` 控制 MCP 工具循环轮数。`model/models` 是新建 Worker 的模型建议。价格可在 `prices` 中按每百万输入和输出 Token 填写，缺少价格时费用显示未知。

Worker 的 API Key 使用平台加密后保存在本机 SQLite 的 Worker 记录中：Windows 使用 DPAPI，其他平台使用 Fernet 和 `data/.ctflow.key`。界面用密码框显示，JSON 导出、持久化运行快照和日志排除密钥。关闭配置窗口会取消未保存的连接修改。跨平台迁移数据库时，需要重新填写 Key。

## Worker、技能与节点

输入 `/worker new` 创建 Worker，输入 `/worker <id>` 编辑已有 Worker。固定上下文用来填写角色要求与长期使用的背景；本次任务放在工作流总任务或节点任务中。按 `Ctrl+S` 保存。点击右上角 `×` 或按 `Esc` 关闭并取消当前修改。

把现成技能复制到 `skill/<名称>/SKILL.md`，再打开 Worker 配置选择对应的 `@名称`。多个技能正文会按所选顺序一起加入模型请求；无效或缺失技能会报告错误。首版加载正文，技能目录中的脚本和附属文件不自动执行或读取。

MCP 服务器先在 `config.json` 中登记，例如：

```json
{
  "mcp_servers": {
    "echo": {
      "transport": "stdio",
      "command": ".venv/Scripts/python.exe",
      "args": ["tests/fixtures/mcp_server.py"]
    }
  }
}
```

保存后打开 Worker 配置，在“MCP 服务器”中填写 `echo`。运行 `ctflow mcp <worker>` 可直接列出该 Worker 能看到的工具，用于排查连接问题。

点击画布节点或双击右侧节点打开装配界面，选择已保存 Worker，并编辑节点名称、补充任务和上游依赖。右侧节点单击只改变选择。Worker 可以被多个节点复用，每次节点执行构造独立上下文。一次运行使用创建时的 Workflow 与 Worker 快照。MCP 服务器在 `config.json` 的 `mcp_servers` 中登记，在 Worker 窗口的“MCP 服务器”字段按名称选择，多个名称用逗号分隔。

## 保存和切换工作流

输入 `/flow` 查看已保存的工作流并选择加载，`/flow new` 新建一套，`/flow edit` 编辑名称、总任务和拓扑。`/flow save` 保存当前图，`/flow save 新名称` 以新 ID 另存，原工作流仍可加载。

图编辑采用界面提示的节点及依赖语法。节点必须引用已保存 Worker；无效引用、自环、循环依赖和悬空节点会拒绝保存。编辑已有节点时，其补充任务按节点 ID 保留。普通输入更新当前工作流总任务。

## 执行与查看

输入 `/run` 执行。没有依赖的节点可并行请求，依赖节点等待直接上游全部成功后启动。一个节点失败时，其下游标记为 `blocked`，独立分支继续运行。输入 `/run stop` 取消在途请求并停止待运行节点。结束后再运行会建立新的 Run。

节点输出按模型流式响应更新，用量取自服务端返回。缺少用量帧时不能由显示数值推断实际账单。未装配 MCP 时模型返回工具调用会失败；装配后由 MCP 会话执行工具并继续请求，最多 `max_tool_rounds` 轮，错误显示在所选节点区域。

`/view result` 汇总本次节点输出；`/export` 保存 Markdown。命令行的 `ctflow list runs` 与 `ctflow show <run-id>` 可以查看已保存运行。运行历史保存于本地数据库；中断进程里的网络连接不会在重启后恢复。

当前最小版聚焦顺序、并行、汇合、停止和 MCP 工具循环；暂停/继续、失败重试、单节点运行、画布拖拽和历史回放属于后续项，详见[实现范围](实现范围.md)。

## 排查

`ctflow doctor` 只检查配置，`ctflow doctor --worker <id> --live` 实际请求一次指定 Worker。模型不可用时检查该 Worker 的模型 ID、接口地址、API Key 和账户权限；输出被截断时调整 `max_tokens` 后重新执行；节点被阻塞时先查看其直接上游的错误。运行测试的方法见项目 README。
